# СпортПростір — онлайн-сервіс бронювання спортивних залів та секцій

Курсова робота з дисципліни
«Документування програмного забезпечення та шаблони проєктування».

Варіант 1.

## Призначення

Вебзастосунок для мережі спортивних центрів, який забезпечує
перегляд спортивних залів і розкладу занять, бронювання послуг,
керування абонементами та взаємодію з клієнтами.

## Реалізовані можливості

- Перегляд спортивних залів і розкладу занять.
- Фільтрація залів за видом спорту.
- Фільтрація занять за видом спорту, рівнем підготовки та віковою категорією.
- Реєстрація, вхід і вихід з облікового запису.
- Редагування профілю, контактних даних, фотографії та спортивних уподобань.
- Бронювання залу на вибраний час.
- Запис на майбутнє заняття.
- Перевірка перетину бронювань і доступності місць.
- Перегляд власної історії бронювань.
- Підтвердження бронювання через імітацію оплати, абонемент або безоплатне обслуговування за правилами лояльності.
- Придбання абонементів через імітацію оплати.
- Перегляд власних абонементів і залишку відвідувань.
- Перегляд картки лояльності та історії бонусних нарахувань.
- Перегляд власних сповіщень, фільтрація та позначення їх як прочитаних.
- Відображення чинних пропозицій відповідно до категорії картки.
- Формування нагадувань про майбутні заняття.
- Адміністративна панель.
- REST API.

Оплата є навчальною імітацією. Реальні кошти не списуються.

## Технології

- Python 3.14.2 — версія середовища розробки.
- Django 5.2.18.
- Django REST Framework 3.17.2.
- django-filter 26.2.
- Pillow 13.0.0.
- SQLite.
- HTML, CSS, JavaScript.
- Git.

Повний перелік залежностей із зафіксованими версіями
міститься у файлі `requirements.txt`.

## Структура проєкту

- `config` — налаштування Django та головні маршрути.
- `accounts` — реєстрація, сесійна автентифікація та профілі.
- `catalog` — спортивні центри, зали, види спорту, секції, тренери та заняття.
- `bookings` — бронювання, імітація оплати та підтвердження.
- `loyalty` — картки лояльності, абонементи та бонусні нарахування.
- `notifications` — сповіщення, нагадування та пропозиції.
- `web` — сторінки користувацького вебінтерфейсу.

## Застосовані шаблони проєктування

### Template Method

Спільну послідовність створення бронювання визначено базовим
процесором. Окремі процесори реалізують перевірку доступності
та розрахунок вартості для оренди залу і запису на заняття.

### Strategy

Правила розрахунку вартості та бонусів винесено в окремі стратегії
для стандартної, преміальної та корпоративної категорій клієнтів.

### Observer

Після підтвердження бронювання публікується подія.
Спостерігачі обробляють створення повідомлення про підтвердження
та бонусне нарахування за відповідними правилами.

## Локальне встановлення у Windows

Команди виконуються в PowerShell із кореневої папки проєкту,
де розташований файл `manage.py`.

### 1. Створення віртуального середовища

```powershell
py -3.14 -m venv .venv
```

### 2. Активація середовища

```powershell
.\.venv\Scripts\Activate.ps1
```

Якщо PowerShell блокує запуск сценарію активації, можна
використовувати Python середовища без активації:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Для наступних команд у такому разі потрібно замінити `python`
на `.\.venv\Scripts\python.exe`.

### 3. Встановлення залежностей

```powershell
python -m pip install -r requirements.txt
```

### 4. Створення структури бази даних

```powershell
python manage.py migrate
```

### 5. Створення адміністратора

```powershell
python manage.py createsuperuser
```

### 6. Запуск сервера

```powershell
python manage.py runserver
```

Сайт: http://127.0.0.1:8000/

Адміністративна панель: http://127.0.0.1:8000/admin/

Для зупинки сервера натисніть `Ctrl+C` у його терміналі.

## Початкове наповнення

Після застосування міграцій нова база даних не містить
демонстраційного каталогу.

Увійдіть в адміністративну панель і додайте:

1. Спортивні центри та види спорту.
2. Спортивні зали з місткістю та погодинною вартістю.
3. Тренерів і спортивні секції.
4. Майбутні заняття з коректними датами, місткістю та вартістю.
5. Тарифи абонементів із відповідною областю застосування.
6. За потреби — пропозиції з періодом дії та цільовою категорією.

Для перевірки користувацьких сценаріїв зареєструйте окремий
обліковий запис через сайт.

Категорію картки лояльності можна налаштувати через
адміністративну панель. Придбання абонемента саме по собі
не змінює категорію картки.

## REST API

| Префікс | Призначення |
|---|---|
| `/api/accounts/` | Реєстрація, вхід, вихід, CSRF та профіль |
| `/api/catalog/` | Каталог спортивних об’єктів і занять |
| `/api/bookings/` | Власні бронювання та їх підтвердження |
| `/api/loyalty/` | Тарифи, власні абонементи, картка та бонуси |

Автентифікація використовує сесії Django.
Запити, що змінюють дані, потребують CSRF-токена.

## Нагадування про заняття

Для формування повідомлень про підтверджені заняття,
які почнуться протягом наступних 24 годин, виконайте:

```powershell
python manage.py send_training_reminders --hours 24
```

Команда створює внутрішні сповіщення в застосунку.
Повторний запуск не створює повторного нагадування для того самого бронювання.

Для автоматичного виконання можна налаштувати
Планувальник завдань Windows:

- програма: абсолютний шлях до `.venv\Scripts\python.exe`;
- аргументи: `manage.py send_training_reminders --hours 24`;
- робоча папка: абсолютний шлях до кореня проєкту;
- періодичність: щогодини.

Сервер розробки не повинен працювати для виконання цієї команди.

## Перевірки

Системна перевірка Django:

```powershell
python manage.py check
```

Перевірка відповідності моделей міграціям:

```powershell
python manage.py makemigrations --check --dry-run
```

Запуск автоматизованих тестів:

```powershell
python manage.py test accounts catalog bookings loyalty notifications web
```

На етапі завершення вебінтерфейсу наявний набір
із 141 автоматизованого тесту пройдено успішно.
Користувацькі сценарії вебінтерфейсу додатково перевірено вручну.

## Особливості роботи

- Нове бронювання створюється зі статусом очікування підтвердження.
- Остаточну вартість і можливість підтвердження визначає сервер.
- Для оренди залу одна одиниця абонемента покриває одну годину;
  неповна година округлюється вгору.
- Для запису на заняття списується одне відвідування.
- Пропозиції відбираються за строком дії та категорією картки.
- Час в історії та повідомленнях відображається за Києвом.
- Команда `runserver` призначена для локального запуску та демонстрації.
